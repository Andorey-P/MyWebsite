# Portfolio Flow Checklist

Use for a complete end-to-end narrative audit. Work top to bottom, matching the arc in [../docs/narrative-structure.md](../docs/narrative-structure.md). Note section/copy for anything that fails, and whether it's a structure problem (fix order/presence of a section) or a copy problem (fix the words — see [copywriting-checklist.md](copywriting-checklist.md)).

## 0. The thesis

- [ ] There is a single, statable narrative thesis for the portfolio (what specific kind of specialist this person is)
- [ ] Every major section (hero, project selection, about, CTA) visibly supports that thesis
- [ ] No project or anecdote is included purely to "show range" at the cost of diluting the thesis

## 1. Hero

- [ ] Role + specialty is stated in real, legible text — not implied only by the 3D scene
- [ ] The claim lands within a 3-second skim budget (one sentence, concrete nouns, no decoding required)
- [ ] Hero does not open with the tech stack as the first clause
- [ ] Primary CTA points at the work (view/see work), not at contact
- [ ] No mission-statement filler, no "welcome to my portfolio" throat-clearing
- [ ] Copy survives independent of the 3D scene loading (screenshot test, slow-connection test)

## 2. Project sequencing

- [ ] Strongest, most thesis-aligned project is first, not chronologically first or alphabetically first
- [ ] The closing project is either the second-strongest or the strongest range/ambition signal — nothing weak is placed last
- [ ] Nothing the author is proud of is buried in the middle purely by accident of order
- [ ] Project count is curated (3–5 typical), not padded with mediocre work to seem prolific
- [ ] Depth varies deliberately — not every project gets an identical full case-study treatment (see pacing in [../docs/narrative-structure.md](../docs/narrative-structure.md))

## 3. Case studies

- [ ] Run [case-study-checklist.md](case-study-checklist.md) per case study

## 4. About page

- [ ] Arrives after the work, not before it
- [ ] Leads with credibility (scannable proof points), not personality or chronology
- [ ] Narrative paragraph has a real turn/reason for the specialty, not a résumé timeline
- [ ] Human-angle detail is specific enough to be falsifiable, not generic ("passionate about tech")
- [ ] Length matches reader investment (roughly 150–300 words of running narrative, not a wall of text)
- [ ] Voice is consistent with the rest of the site (not a stiffer/more corporate register than the hero/case studies)

## 5. CTA / conversion

- [ ] A single, unambiguous primary CTA exists site-wide (not competing asks in multiple places)
- [ ] Contact path is fast — real email/LinkedIn visible, not gated behind a form as the only option
- [ ] CTA copy is specific to what happens next, not a generic "Contact Me" with no context (see [../snippets/cta-copy-patterns.md](../snippets/cta-copy-patterns.md))

## 6. Cross-page / cross-section consistency

- [ ] Voice is consistent across hero, case studies, about, and microcopy (nav labels, loading states) — see [../snippets/microcopy-patterns.md](../snippets/microcopy-patterns.md)
- [ ] Any entry point that isn't the homepage (a shared case-study link) restates enough identity to not feel orphaned, without repeating the full hero
- [ ] No dead links, placeholder text, or "coming soon" cards in the live flow (a distrust signal — see [../docs/recruiter-employer-psychology.md](../docs/recruiter-employer-psychology.md))

## 7. Three-reader test

- [ ] A 30-second skim (recruiter) extracts role + one differentiator + a way to see more
- [ ] A slower pass (creative director) finds at least one case study with real evidence of decision-making, not just a finished screenshot
- [ ] A technical pass (senior engineer) finds at least one named mechanism (not just tool names) explaining how a hard problem was actually solved

## Close with

- [ ] Prioritized list of the 3–5 narrative/copy changes that matter most, highest impact first
