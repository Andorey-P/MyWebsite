# Case-Study Template

Fill-in skeleton for a full case study. Full rationale for each section in [../docs/project-case-study-structure.md](../docs/project-case-study-structure.md). Not every project needs every section at full length — see pacing in [../docs/narrative-structure.md](../docs/narrative-structure.md). When done, run [../checklists/case-study-checklist.md](../checklists/case-study-checklist.md).

---

## [Project Name]

### Hook / overview
*One to two sentences. What this is, and the single most interesting thing about it. Must survive being read alone — a skimmer reads only this.*

> [What it is] for [who it was for] — [the one thing that makes it interesting: a technical feat, a creative concept, a constraint solved].

### The brief / problem
*What was being solved, in the client's/project's own terms, not technical terms yet. Include real constraints — timeline, budget, existing brand system, target device/audience limits. Constraints are what make the coming decisions meaningful.*

> [Who asked for what, and why it mattered to them.] [The real constraint(s) that shaped everything downstream: timeline was X, had to work on Y devices, had to respect Z existing system.]

### Process & key decisions
*Told through decisions, not a diary. For each major decision: option chosen, option(s) rejected, why. Aim for the 1-3 decisions that actually mattered, not a full timeline.*

**Decision 1: [what was decided]**
> [What was tried/considered first, why it didn't work, what was chosen instead, and why.]

**Decision 2: [what was decided]** *(optional — only if there's a second decision worth explaining)*
> [Same structure.]

### The technical/creative challenge
*The hardest problem on this project. Name the actual mechanism/bottleneck — not "it was complex." State the concrete fix and, if available, a real measured result.*

> The hardest problem wasn't [the obvious thing] — it was [the actual bottleneck/challenge, named specifically]. [How it was diagnosed/understood.] Solved by [the specific technique/mechanism], which [concrete, ideally measurable result].

### Outcome
*What actually happened. Separate measurable facts from claims you can't verify. Don't fabricate a number — an honest qualitative statement beats an invented precise one.*

> [Shipped/live status.] [Any real metric: load time, frame rate, award, client outcome.] [If nothing is quantifiably measurable, say what's true and verifiable instead: "shipped on time and is still live at X."]

### Reflection *(optional but valuable — a real seniority signal)*
> If I rebuilt this today, I'd [specific thing you'd do differently] — [why, briefly].
